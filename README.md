# Friend — виртуальный компаньон

2D-персонаж (пиксельная девушка), которая живёт поверх всех окон: разговаривает,
помнит разговор, меняет тон по времени суток. Не ассистент — спутник.

План по этапам и принятые решения — в [PLAN.md](PLAN.md).

## Откуда берётся модель

Модель описана в конфиге — файл `%AppData%\Friend\config.json` (Windows) или
`~/.config/Friend/config.json` (Linux). В нём три поля, которых достаточно для
любого OpenAI-совместимого API:

```json
"llm": {
  "base_url": "http://127.0.0.1:11434/v1",
  "model": "gpt-oss:120b-cloud",
  "api_key_env": ""
}
```

- `base_url` — адрес API (NVIDIA NIM, локальная Ollama, любой другой провайдер);
- `model` — имя модели у этого провайдера;
- `api_key_env` — **ИМЯ** переменной окружения с ключом. **Пустое имя значит
  «ключ не нужен»** — так подключают локальные модели (Ollama, LM Studio,
  llama.cpp). Значение ключа в конфиге не лежит никогда и в логи не попадает.

Конфига нет — работают значения по умолчанию: NVIDIA NIM и переменная
`NVIDIA_API_KEY`. Ниже — три варианта, из чего выбирать.

### Вариант 1. Локальная Ollama (так настроено сейчас)

У неё тот же `/v1/chat/completions`, что и у облачных API, поэтому подходит без
правок кода: `base_url` — `http://127.0.0.1:11434/v1`, `api_key_env` — пустая
строка. Проверить, что она жива:

```bash
curl -s http://127.0.0.1:11434/api/tags
```

Две тонкости этой машины (проверено):

- модель **`gpt-oss:120b-cloud`** отвечает за секунду — она считается на стороне
  ollama.com, поэтому нужен интернет и вход в аккаунт Ollama;
- модель **`llama3.1:8b`** на этой видеокарте падает с ошибкой CUDA
  (`device kernel image is invalid` — драйвер и библиотека CUDA разошлись). Если
  нужен полностью локальный вариант, поднимите Ollama БЕЗ GPU и укажите её адрес:

  ```bash
  CUDA_VISIBLE_DEVICES=-1 OLLAMA_NUM_GPU=0 OLLAMA_HOST=127.0.0.1:11499 ollama serve
  ```

  Ответ на 8B идёт около 18 секунд (холодный старт), поэтому в конфиге с ней
  стоит увеличить `llm.timeout_sec` до 90.

### Вариант 2. NVIDIA NIM — только там, где регион не заблокирован

NVIDIA отдаёт **451** (недоступно по юридическим причинам) на ЛЮБОЙ запрос из
закрытых стран — даже на список моделей, ещё до проверки ключа. То есть при 451
ключ в порядке, и чинить в нём нечего. Проверить одной командой:

```bash
curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer $NVIDIA_API_KEY" https://integrate.api.nvidia.com/v1/models
```

`451` — провайдер закрыт для твоего региона: вариант решения — VPN или прокси
(сервер уважает переменные `HTTP_PROXY`/`HTTPS_PROXY`), локальная модель
(вариант 1) или другой провайдер (вариант 3). В окне компаньона это сообщение
теперь так и написано — раньше на 451 было просто «API ответил ошибкой (451)».

### Вариант 3. Другой провайдер

Достаточно поменять `base_url`, `model` и имя переменной с ключом. Проверено с
этой машины (2026-10-16): отвечают `api.deepseek.com`, `api.mistral.ai`,
`api.z.ai`, `api.proxyapi.ru`, `api.vsegpt.ru`; не отвечают вовсе (403 на
cloudflare) `openrouter.ai`, `api.groq.com`, `api.openai.com`,
`generativelanguage.googleapis.com`, `api.anthropic.com`.

Пример на DeepSeek: в конфиге `"base_url": "https://api.deepseek.com"`,
`"model": "deepseek-chat"`, `"api_key_env": "DEEPSEEK_API_KEY"`, а в `.env` —
строка `DEEPSEEK_API_KEY=...`.

### Ключ в файле `.env`

Ключ (если он нужен) лежит в файле **`.env`** в корне проекта, рядом с `start.bat`:

```
NVIDIA_API_KEY=nvapi-...
```

Пошагово:

1. Открой `C:\Users\Tima\Desktop\Friend\.env` блокнотом.
2. Вставь ключ после `NVIDIA_API_KEY=` (ключ выглядит как `nvapi-...`).
3. Сохрани. Запусти `start.bat` заново — сервер читает этот файл **один раз при
   запуске**, поэтому правку на лету он не видит.
4. Проверить: в окне консоли будет строка

   ```
   level=INFO msg="файл ключей прочитан" file=...\Friend\.env переменные=[NVIDIA_API_KEY]
   level=INFO msg="модель готова" состояние="модель openai/gpt-oss-20b, ключ есть (NVIDIA_API_KEY)"
   ```

   Если вместо этого «файла ключей .env нет» — сервер запущен не из корня проекта;
   если «ключа нет» — строка пустая (значение после `=` не дописано).

Правила, которые здесь заложены:

- файл **не попадает в git** (см. `.gitignore`), значение никогда не печатается в
  логи — в логе видно только имя переменной;
- настоящая переменная окружения **сильнее** файла: если `NVIDIA_API_KEY` задана в
  системе, берётся она;
- имя переменной настраивается (`llm.api_key_env` в конфиге), но тогда строка в
  `.env` должна называться так же;
- пустое имя переменной означает «ключ не нужен» (локальная модель), а пустое
  ЗНАЧЕНИЕ при заданном имени — это по-прежнему «ключа нет»: конфиг не должен
  уметь незаметно превращать запрос с ключом в анонимный;
- без ключа персонаж работает: живёт, таскается, открывает окно ввода, но на
  реплику отвечает объяснением, где взять ключ — а не молчит.

Если ключа нет вовсе, а посмотреть на неё хочется — просто не заполняй `.env`.

## Что уже работает

**Этап 1 — каркас**

- Go-сервер: конфиг, логи с уровнями, состояние на диске, WebSocket, `/healthz`.
- Перетаскивание мышью; позиция сохраняется и восстанавливается при запуске.
- Оболочка Electron: прозрачное окно без рамки, always-on-top, сама поднимает
  сервер, если он не запущен.

**Меню: размер, посадка, облачко** (по мотивам Desktop Mate и MateEngine)

- **Правая кнопка по самому персонажу** открывает меню; по пустому месту рядом —
  нет (окно шире её, и меню там отнимало бы клик у рабочего стола).
- В меню: **размер** ползунком (2–12 пикселей на клетку спрайта; колесо мыши над
  персонажем делает то же), **посадка** (свободно / на панель задач / **на окне** /
  у левого или правого края экрана), **сила слежения за курсором** ползунком
  (0–100 %, см. пункт ниже), переключатели «поверх всех окон», «говорит вслух»,
  «слышит её имя», «запускать при входе», действия «поговорить / помахать /
  домой / выход».
- **На панель задач она садится** (поза сидя): низ спрайта — это то, на чём она
  сидит, и он же ставится на верхнюю кромку панели. Кромку знает оболочка —
  рабочая область Windows уже без панели задач, поэтому «панель высотой 40» или
  перенесённая панель не требуют угадывания.
- **На окне она сидит на его верхней кромке** (посадка «на окне»): помощник
  активного окна передаёт оболочке ещё и **прямоугольник окна на экране** —
  это геометрия, не содержимое: в модель по-прежнему уходят только процесс и
  заголовок, границы окна живут только в странице. Сидит — следует за активным
  окном: перешёл человек в другую программу, она переехала на его верх.
  Верх слишком высоко (окно выше её по высоте) — ноги встают туда, куда окно
  физически влезает; по горизонтали — внутри мишени, над краем окна она не
  висит. Нет активного окна (рабочий стол, блокировка) — говорит «не на что
  сесть» и остаётся свободной.
- **Посадка удержанием («удержание перед посадкой» из MateEngine).** Тащит её
  человек мышью, её ноги входят в полосу верхней кромки активного окна (±36 px)
  и стоят там **полную секунду** — она садится на окно, а протяжка привязывается
  к новому месту (дальше тащится от кромки, а не «из-под неё»). Быстрый пролёт
  через кромку не сажает: у него нет секунды.
- **Сила слежения за курсором — ползунок (0–100 %, как в MateEngine).** 0 — за
  курсором не следит вовсе: зрачки стоят посреди глаз. 100 — провожают взгляд до
  предела, то есть на один пиксель спрайта: дальше взгляд уже не взгляд, а
  вывернутые глаза, поэтому предел заложен в аватаре, а ползунок решает,
  насколько зрачки до него доезжают. По умолчанию 80 %. Прежняя настройка была
  булевой (галка «смотрит за курсором»): включённая переезжает в 80 %
  автоматически, выключенная — в 0, после обновления ничего перенастраивать не
  нужно.
- **У края экрана она выглядывает по-настоящему.** Окно встаёт кромкой ровно к
  краю экрана, а прячется и выходит движение спрайта внутри окна: обрезку делает
  сама картинка, поэтому она исчезает ровно по краю экрана, а не остаётся
  обрезанной полосой. Она садится за кромку на 4–9 секунд, потом выезжает
  (плавно, около секунды), стоит на виду 2,5–5 секунд, иногда машет и уходит
  обратно; паузы случайные, чтобы движение не стало метрономом. Подвёл мышь к
  кромке — она выглядывает сразу, не дожидаясь своей паузы; то же самое при
  реплике: ответ не должен приходить в пустоту. Пока открыт разговор или идёт
  ответ, она не прячется.
- **Размер окна больше не «съезжает».** По протяжке было видно, как окно растёт
  на глазах, а вместе с ним растягиваются облачко реплик и поле ввода («на весь
  экран»). Причина оказалась в оболочке: `BrowserWindow.setPosition` на этой
  системе растит окно примерно на 1,3 пикселя за вызов, а протяжка делает их
  шестьдесят в секунду. Теперь переезд идёт через `setBounds` с ЯВНЫМ размером
  (размер берётся только у страницы, никогда не читается обратно у окна), а
  сторож раз в 3 секунды возвращает размер, если он всё-таки уехал. Проверка:
  протяжка в 120 шагов оставляет окно 248×375 неизменным и довозит его за
  курсором (отклонение 4×8 пикселей).
- **Облачко реплик больше не растёт бесконечно.** Окно больше спрайта на
  постоянные поля (84 над головой, 24 по бокам), высота облачка — это поле над
  головой, а не процент от окна: длинная реплика прокручивается внутри облачка, а
  не растягивает окно. Раньше при маленьком окне влезало две строки, при большом
  облачко наезжало на лицо.
- **Пока меню открыто, окно расширяется вбок** (в сторону, где есть место на
  экране) и возвращается обратно при закрытии. Персонаж при этом остаётся на
  месте: точка отсчёта — его ноги на экране, а не центр окна.
- Размер и посадка запоминаются между запусками (настройки страницы), позиция —
  по-прежнему на сервере.

**Этап 2 — диалог**

- Персонаж **пиксельной аниме-девушкой** (голубые волосы, золотые глаза): сетка
  40×56 с общей палитрой и контуром. Моргает, дышит, смотрит за курсором, умеет
  эмоции (спокойная, радость, грусть, задумчивость, сон), разговаривает (рот
  открывается, пока идёт реплика), машет рукой на клик.
- **Поглаживание:** если водить мышью туда-сюда по волосам две-три секунды
  (двух спокойных взмахов ладонью хватает) — она улыбается и вокруг неё летят
  пиксельные сердечки. Раньше порог был жёстче (две секунды непрерывного
  движения строго по голове): живой человек водил курсором по голове —
  реакции ноль, потому что на каждом развороте курсор на долю секунды
  съезжал с головы и обнулял счёт. Теперь короткий вылет за край волос
  счёт не сбрасывает, а порог — два взмаха, а не марафон.
- **Сон и «Zzz»:** когда она засыпает сама (пропал надолго — см. инициативу),
  реплика приходит с полем `emotion: "sleep"`: она закрывает глаза прямо во
  фразе, и над головой раз в полторы секунды рождается пиксельная «Z», уплывает
  вверх-вправо и тает. Разбудить её может только набор текста.
- **Сон/уход после простоя:** сама тишина тоже будит режим сна: 10 минут без
  движения мыши и клавиатуры — она засыпает (глаза закрыты, «Zzz»); 30 минут —
  «уходит»: переезжает к ближайшему краю экрана и спит там, выглядывая, когда
  подводишь курсор (тот же край-механизм, что в меню «у края»). Вернулся —
  оживает и возвращается ровно на то место, где стояла. Простой считается на
  странице: поле `idle` кадров помощника (GetLastInputInfo) плюс твои
  действия у неё (мышь по персонажу, клик, меню, чат, её голос из колонок,
  начавшийся танец). Занятую — её держат, идёт разговор, она шагает, танцует,
  говорит — сон и уход не трогают; возвращение будит в том числе и занятую.
- **Прогулка:** когда ты рядом, но молчишь, она время от времени гуляет по
  рабочему столу: перебирает ногами (ведомая нога полупрозрачная, передняя
  выходит за силуэт), тело покачивается в такт шагу, окно едет (~30 px/с),
  у края экрана она разворачивается. Её взяли мышью / открыли меню / заговорили
  — прогулка сразу кончается, место запоминается.
- **Микроживость (этап 9а):** в бодром простое она не «статуя»: каждые
  полминуты-минуту случается микродвижение — потянется обеими руками,
  почешет затылок, ёрзнет на месте, посмотрит на свою ладошку (наклон идёт
  вокруг талии, движение поднимается и гаснет по синусу — без «включил
  анимацию»). Речь, шаг, танец, взмах, сон и режим листа микроживость
  перекрывают.
- **Ходьба по экрану в простое:** если человека рядом нет долго (5–10 минут
  тишины), прогулка иногда превращается в **длинный проход**: она идёт к
  дальнему краю стола, разворачивается там и переходит на другой край — через
  весь рабочий стол, — и останавливается. Не «туда-сюда на десять секунд», а
  маршрут на весь экран. Кадры ног при этом дорисовываются телу прямо в его
  сетку (раньше уезжали за край сетки — и «ноги пропадали, когда она бегает
  по экрану»); ведомая нога полупрозрачна, передняя выходит за силуэт.
- **Голос (этап 7, озвучка Edge TTS):** её реплики произносятся вслух голосом
  `ru-RU-SvetlanaNeural` (бесплатный сервис Microsoft, ключа не нужно — нужен
  пакет `edge-tts`, он стоит на этой машине и виден в PATH). Готовые фразы
  кэшируются локально (`%AppData%\Friend\tts`), повтор звучит мгновенно.
  **Интонация по настроению (этап 9б):** радостная говорит чуть быстрее и
  выше (`+12 %/+8 Гц`), грустная — медленнее и ниже (`−12 %/−6 Гц`), сонная
  — заметно медленнее и низко (`−25 %/−10 Гц`, сон важнее настроения).
  Ключ кэша включает тон: одна и та же фраза, сказанная по-разному, —
  отдельные файлы.
  Переключатель «говорит вслух» — в меню. **Приватность:** в облако Microsoft
  уходит только ТЕКСТ её реплики; экран, память и история туда не попадают.
  `voice.enabled: false` в конфиге — функция полностью выключена.
- **Эмпатия по тону (этап 9в):** она чувствует, КАК ты пишешь, и подстраивается.
  Детектор тона работает локально (Go-пакет `moodread`, список корней слов):
  из твоих сообщений собирается ярлык — «устал», «расстроился», «рад»,
  «злится», «тревожится». Ярлык попадает в её промпт как её собственное
  наблюдение («он сейчас расстроился — учти это в тоне ответа»), и она
  отвечает сочувствием: после своей фразы на несколько секунд становится
  грустнее (грустный → лицо «sad», усталость и тревога → задумчивое, радость
  → улыбка), потом возвращается к своему спокойному лицу. Нейтральные
  сообщения не вызывают ничего. **Приватность:** ярлык считается на машине,
  в память не записывается, в облако TTS не уходит; модель видит только одно
  слово тона, а не разбор твоих сообщений.
- **Голосовой ввод (этап 7, локальный faster-whisper):** в поле ввода появилась
  кнопка микрофона. Нажал — говоришь вслух — его слова появляются в поле, где
  их можно прочитать и поправить до отправки. Расшифровка идёт ПОЛНОСТЬЮ
  локально: Python + `faster-whisper` (модель base, 75 МБ, лежит в
  `%AppData%\Friend\stt-model\`) — запись с микрофона никуда не уходит, в
  отличие от озвучки, где в Microsoft летает только текст её реплики. Нужен
  python с `pip install faster-whisper` (модель скачивается один раз).
  Микрофон при записи пульсирует красным; потолок записи — минута; кнопка
  видна только когда сервер заявил расшифровку. `stt.enabled: false` в
  конфиге — голосовой ввод полностью выключен.
- **Слышит её имя (этап 7, wake word):** скажи «Мира, …» вслух — она оживает,
  будится (если спала), машет и коротко отвечает на имя, а сказанные ей слова
  уходят в разговор как напечатанные (она отвечает по сути). Фоновый слушатель
  держит микрофон открытым, но ничего не пишет и не отправляет подряд:
  локальный VAD режет речь на куски, каждый кусок расшифровывается локальным
  faster-whisper и ищет её имя; не имя — текст выбрасывается. Функция
  по умолчанию ВЫКЛЮЧЕНА (микрофон постоянно открыт только по твоему
  решению): включается переключателем «слышит её имя» в меню и требует
  `wake.enabled: true` в конфиге. Пока слушает — в углу окна горит зелёная
  точка-индикатор. Эхо-защита: она не будит себя собственным голосом из
  динамиков.
- **Танцует под музыку (этап 7, «реакция на звук»):** заиграла музыка на
  колонках — она оживает: тело подпрыгивает в такт измеренному темпу, волосы
  качаются в такт, рука поднимается на «раз-два», лицо — улыбка (спящую
  будит). Замолчала — через восемь секунд танец кончается, лицо возвращается
  к настроению. Переключатель «танцует под музыку» в меню, по умолчанию
  ВЫКЛ: слушать системный микшер фоном без явного желания человека нельзя.
  **Приватность:** системный микшер (не микрофон) читает Go-помощник
  `soundwatch.exe` (WASAPI loopback): из звукового сигнала он наружу отдаёт
  РОВНО RMS-уровень — одно число. Звук нигде не сохраняется и никуда не
  отправляется: сервер и модель не получают даже факта танца. Её собственная
  озвучка из тех же колонок в микшер попадает, но танец НЕ продлевает:
  музыка кончилась — танец кончается, даже если она продолжает говорить
  реплики (голос в тишине без музыки для детектора — тишина).
- **Свой арт:** если подложить свои PNG-кадры в папку `%AppData%\Friend\sprites`
  вместе с файлом `sheet.json`, персонаж целиком становится картинкой текущего
  состояния. Кадр выбирается по состоянию: шаг (walk1/walk2, шаги влево —
  зеркально), моргание (blink), речь (talk), взмах (wave), эмоция
  (happy/sad/think/sleep), поза (sit), база (stand). Отсутствующий кадр
  проваливается к базе — лист из трёх картинок тоже работает. Папку убрать —
  возвращается нарисованная кодом Мира.
- **Реакция на клик:** клик по персонажу (нажала и отпустила, мышь не
  сдвинулась) — она коротко отвечает локальной фразой из пула («М?», «Я тут.»,
  «Хм? Что стряслось?») — без ключа модели и сети, и открывает окно ввода.
  Спящую клик будит («Мм? Да, я тут.»). Частые тычки не превращают её в
  автомат: ответ один на десять секунд, дальше — молча.
- Разговор: клик по персонажу открывает окно ввода, `Enter` — отправить,
  `Shift+Enter` — перенос строки, `Esc` — закрыть. Её ответ появляется в облачке
  над головой, пока она «думает», в облачке крутятся точки.
- Контекст: последние 20 реплик (`llm.history_messages`) уходят в запрос вместе с
  системным промптом, который собирается на каждую реплику (время суток меняет
  тон). История живёт в памяти сервера и приходит окну при подключении —
  перезагрузка страницы не выглядит как «она меня забыла».
- Женский род: характер содержит `"gender": "female"`, и промпт требует говорить о
  себе только в женском роде («я пришла», «я рада») — раньше модель путала род.
- Ошибки объясняются человеку, а не молчанием: нет ключа, ключ не принят, модель
  не найдена, модель израсходовала лимит на «размышления», API молчит.

**Понимание окна и инициатива (этап 4)**

- Оболочка запускает помощника `focuswatch.exe`: он спрашивает Windows, какое окно
  сейчас в фокусе, — **только имя процесса и заголовок**, ни строчки содержимого —
  и присылает смену окна через страницу на сервер (кадр `focus`).
- Сервер классифицирует приложение (`internal/focus`): GoLand и VS Code — «код»,
  Chrome — «браузер», Telegram — «переписка», Steam — «игра», терминал, музыка,
  офис. Неизвестное приложение проходит как «неизвестное» с прямым запретом модели
  что-либо выдумывать.
- В системный промпт на каждую реплику попадает одна строка: «Он сейчас в GoLand
  (IDE для Go), уже 2 ч — не перебивай без нужды. Содержимое окон не описывай и
  не угадывай». Счёт «уже» начинается с последней смены приложения; смена вкладки
  его не обнуляет.
- Приватность: список приложений и заголовки живут только в памяти сервера и в
  тексте запроса к модели; наружу (кроме API) ничего не уходит. Окно самой Миры и
  рабочий стол в промпт не попадают.
- Оболочка перезапускает помощника, если тот умер; на Linux/macOS персонаж
  работает без понимания окна (помощника там нет), сервер — честно без строки
  обстановки.
- Кадры `focus` несут ещё и поле `idle` — сколько минут человек не трогал мышь
  (`GetLastInputInfo`). Раз в 30 секунд помощник присылает heartbeat с свежим
  idle, даже если окна не меняются: «его нет рядом» обновляется, а не замирает.

**Инициатива (вторая половина этапа 4)**

Она заговаривает сама, когда обстановка того просит, — и умеет молчать, когда
просит не просить. Планировщик `internal/proactive` — чистая функция: на каждый
тикт (по умолчанию 30 с) подаётся обстановка, на выходе повод.

Поводы, в порядке важности:

| Повод | Условие | Пример реплики |
|---|---|---|
| «иди спать» | после 3:00, раз за ночь | «Я устала. И ты иди. Спокойной ночи.» |
| она засыпает | 25 мин без мыши, раз в 2 ч | «Зе… я зеваю.» |
| вода/еда | по конфигу, по умолчанию 3 ч | «Воду не забыл?» |
| марафон в приложении | 2 ч в одном окне, один раз на заход | «Код не убежит. Может, чай?» |
| приветствие | смена части суток (утро/вечер) | «Доброе утро» |
| молчание | 60 мин без разговора, если он НЕ занят | мягко появиться |

Правила тишины:

- **Не чаще одного сообщения в 25 минут** (настройка), а если он занят
  (редактор кода, игра, офис, терминал) — пауза вдвое дольше. «Занят → реже».
- **Окно тишины 23:00–7:00:** спит всё, кроме «иди спать» и её собственного
  засыпания.
- **Однократно по поводу:** чай по трёхчасовому GoLand — одна реплика на этот
  заход в приложение; ушёл и вернулся — счёт обнуляется.
- **Повторный намёк не раньше чем через 5 минут** — неудачная попытка
  (нет связи, модель молчит) не превращается в стук.
- Повод — служебная инструкция модели («заговори первой по поводу…»), в
  историю разговора не попадает: там остаётся только её реплика.

На экране это видно: облачко «заговорила сама» с тёплым контуром, и она машет
рукой — реплику не спутать с ответом на набранный текст.

Живая проверка ускоренным временем (тик 2 с, окно тишины снято, модель —
локальная Ollama из рабочего конфига):

```bash
cd server
go build -o ../bin/companion.exe ./cmd/companion
go build -o ../bin/proactivetest.exe ./cmd/proactivetest
../bin/companion.exe -config ../fast-proactive.json        # консоль с логом
../bin/proactivetest.exe -addr 127.0.0.1:8899 -idle 50 -wait 90s
# ПРОАКТИВНАЯ РЕПЛИКА: "Зе… я зеваю." — OK   (в логе: заговорила сама kind=idle)
```

`proactivetest` подключается к серверу как окно, присылает кадр `focus` с
`idle=50 минут` и ждёт бродкаст `reply` с флагом `proactive:true`. По idle-поводу
кадр несёт ещё `emotion:"sleep"` — окно закроет ей глаза и пустит «Zzz».

**Память (этап 3)**

Её долгая память живёт в SQLite-файле `memory.db` в каталоге пользователя
(`%AppData%\Friend\memory.db`) — наружу из него не уходит ничего. Три слоя:

- **Архив разговора** — все реплики. При старте сервера последние N реплик
  возвращаются в живую историю: после перезапуска она помнит вчерашний
  разговор, а не начинает с чистого листа.
- **`запомни: …`** — команда в окне ввода: напиши «запомни: кот Барсик», и она
  ответит «Запомнила: кот Барсик» и запомнит. Работает **без ключа модели**
  (память локальная). В следующий раз, когда речь про кота, факт попадёт в её
  системный промпт сама — без просьбы вспоминать.
- **Ночное саммари** — на смене части суток в ночь модель сжимает разговор за
  сутки в одну заметку о тебе («Тим весь вечер кодил, злился на баги») и
  кладёт в базу. Один раз на день; при паре реплик за день саммари не делается.

Поиск по фактам — SQLite FTS5 с усечением слов («отец*» найдёт «отца»,
«кот*» найдёт «кота»): падежи ловит, whole-совпадений не требует. В промпт
попадает подборка (≤5 фактов + вчерашнее саммари) с прямым запретом
пересказывать список — память работает как её знание, а не как цитата.

Живая проверка (та же, что в логах):

```bash
../bin/companion.exe -config ./fast-memory.json
../bin/proactivetest.exe -addr 127.0.0.1:8898 -remember "кота зовут Барсик"
# ОТВЕТ (подтверждение запоминания): "Запомнила: кота зовут Барсик" — OK
../bin/proactivetest.exe -addr 127.0.0.1:8898 -ask "Как зовут моего кота?"
# ОТВЕТ (ответ): "Твой кот – Барсик. 🐾" — OK   ← факт из памяти
# перезапуск сервера → «история восстановлена из памяти, реплик=4» → новый
# вопрос про кота → «Конечно, твоего кота зовут Барсик» — память жива
```

`proactivetest` умеет три режима: без флагов — ждать проактивную реплику
(этап 4), `-remember "текст"` — проверка команды памяти, `-ask "текст"` —
проверка контекста (обстановка и память в живом ответе).

**Состояние и настроение (этап 5)**

У неё есть внутреннее состояние — три значения 0..1, живущие в
`internal/mood` (чистая модель, проверяется на фейковых часах):

- **Настроение** — поднимается, когда человек сам пишет (тем сильнее, чем она
  к нему привязана), и падает, когда её реплику игнорируют (проверка через
  30 минут после её проактивной фразы) или после 4 часов молчания.
- **Энергия** — ползёт к целевой по части суток: утро бодрое (0.75),
  ночь усталая (0.20), не быстрее 0.08 в час: резких скачков не бывает.
- **Привязанность** — растёт от разговоров, тает за долгое отсутствие
  (пол 0.20 — неделя без общения не делает её равнодушной).

Что с этим происходит:

- В системный промпт каждой реплики (и ответа, и её собственной инициативы)
  ложится одна строка: «настроение — приподнятое; энергия — усталость,
  сонливость; отношение — очень привязана к человеку» с запретом пересказывать
  состояние цифрами и жаловаться на него — тон её речи меняется, человек этого
  не читает таблицей.
- На лице — полоска настроения: грустинка / спокойствие / лучезарность.
  Событийные лица (сон, улыбка от поглаживания, «думает») полоской не
  перебиваются, а после события лицо возвращается к настроению, а не к
  дежурному спокойствию: упало настроение — грустнеет лицо.
- Состояние сохраняется в `state.json` между запусками (пишется только
  заметный сдвиг ≥0.05) и приходит окну в welcome — после перезагрузки
  лица соответствующие пережитому.

Живая проверка: реплика человека → тик цикла → в логе
`состояние сдвинулось mood=0.967 band=high` → запись в `state.json`; после
ребута сервера — `настроение mood=0.967`.

**Трей и автозапуск**

У окна компаньона нет рамки, и раньше «закрыть окно» означало расстаться с ней.
Теперь закрытие — это прятанье, а не исчезновение:

- Значок в трее — **настоящий снимок её окна** (какая она сейчас: поза, размер,
  лицо), пока окно не собралось — базовое личико, нарисованное оболочкой.
- Двойной клик по значку и пункт «показать / скрыть» возвращают её на экран
  и убирают с него.
- Закрытие окна (Alt+F4, «закрыть окно» любой программы) прячет Миру в трей:
  сервер, озвучка и фоновый слушатель продолжают жить — персонаж не «умирает»
  от случайного нажатия.
- «Выход» — из меню трея или из её собственного меню — выход настоящий,
  с остановкой сервера.
- «Запускать при входе» — галка в её меню: пишет штатный ключ автозапуска
  Windows (`HKCU\...\Run`, без администратора) и восстанавливает его при
  следующем старте, если человек удалил запись во вкладке «Автозагрузка»
  Диспетчера задач. По умолчанию выключено: без явного желания реестр не
  трогает. Применение — по ответу оболочки: не вышло — галка не остаётся.

Живая проверка: Alt+F4 по окну — её не видно, значок в трее; двойной клик —
она на месте, в прежней позе. Включи «запускать при входе» — в вкладке
«Автозагрузка» Диспетчера задач появится запись Electron с папкой приложения;
выключи — пропадает.

## Запуск

Проще всего — двойной щелчок по **`start.bat`** в корне проекта (Windows). Он:

1. проверяет, что есть Go и Node (иначе скажет об этом, а не мигнёт окном);
2. закрывает прошлый запуск (**и окно, и сервер**) и **пересобирает сервер** —
   каждый раз: серверный код без пересборки даёт сервер и страницу из разных
   версий, а старое окно продолжает работать по старому коду оболочки;
3. один раз ставит оболочку (`npm install`), дальше пропускает этот шаг;
4. открывает персонажа. Сервер окно поднимает само.

Тащи мышью за самого персонажа — она запомнит место. Второе окно не откроется:
компаньон один (два окна спорят за сохранённую позицию).

**Закрыть:** Alt+F4 по окну прячет её в трей — это штатный «увести с глаз»,
обратно — двойной клик по значку. Выйти по-настоящему (вместе с сервером) —
«Выход» в меню трея или «выход» в её меню; радикально — закрыть окно консоли,
из которого запущен компаньон.

Вручную, если хочется по шагам:

```bash
cd server
go test ./...                                  # конфиг, состояние, канал, разговор, планировщик, память
go build -o ../bin/companion.exe ./cmd/companion
go build -o ../bin/focuswatch.exe ./cmd/focuswatch   # помощник окна (оболочка его сама не собирает)
go build -o ../bin/soundwatch.exe ./cmd/soundwatch   # помощник звука для танца (то же)
cd ../desktop && npm install && npm start
```

Память (SQLite) поднимается сама при первом запуске — файл `memory.db` в
`%AppData%\Friend\`, рядом с `state.json`. Ничего отдельно ставить не надо.

Нужны Go 1.24+ и Node 18+.

### Модель

Какой провайдер отвечает, решают `llm.base_url` и `llm.model` — см. «Откуда
берётся модель» выше (NVIDIA, локальная Ollama или другой провайдер). При
работе через NVIDIA по умолчанию `openai/gpt-oss-20b` — самая быстрая из
доступных по ключу (ответ 2–7 секунд). Модель у того же провайдера меняется в
конфиге:

```json
"llm": { "model": "nvidia/nemotron-3-super-120b-a12b", "max_tokens": 1024 }
```

Важно про лимит токенов: часть моделей NIM перед ответом «думает», и на маленьком
`max_tokens` вызов заканчивается по длине с ПУСТЫМ ответом. При 300 токенах это
случалось через раз, при 1024 — не наблюдалось. Если увидишь ошибку про лимит —
увеличь `llm.max_tokens`.

### Почему персонаж не может «потеряться»

Окно можно потерять по-разному, и каждый случай закрыт отдельно:

| Что случается | Что с этим сделано |
|---|---|
| В памяти окна сохранилась точка за пределами экрана (отключили монитор, поменяли разрешение, записались битые координаты) | Оболочка клампит позицию в рабочий стол при **любом** переезде; если окно поставили не туда, куда просили, страница отправляет серверу настоящее место — память сама исправляется |
| Окно «дрыгается по всему экрану» при перетаскивании после такой точки | Точка отсчёта протяжки пересчитывается, когда окно не доехало до цели (упёрлось в край или его поправила оболочка) |
| Монитор отключили/включили, сменился масштаб | Сторож в оболочке слушает изменения экранов и возвращает окно |
| Окно свернули, скрыли, оно потеряло «поверх всех» | Сторож раз в 3 секунды проверяет и чинит (`restore`, `show`, `setAlwaysOnTop`) |
| Страница упала или не загрузилась — окно осталось пустым и прозрачным | `render-process-gone` / `unresponsive` / `did-fail-load` → страница перезагружается, ошибка печатается в консоль |
| Кадры перестали рисоваться, хотя окно на месте: подвис драйвер, потерялся контекст WebGL, исключение в кадре | Страница на каждом нарисованном кадре бьёт «пульсом»; если пульса нет 9 с, оболочка спрашивает страницу «цикл жив?» и перезагружает её. Если страница отвечает «рисует» (окно перекрыто, экран погашен) — не трогает, чтобы не мигать без причины |
| Контекст WebGL потерян, графический процесс упал | страница перезагружает себя сама по `webglcontextlost`; оболочка — по `child-process-gone` типа GPU |
| Компьютер вышел из сна, экран разблокировали | по `powerMonitor` окно возвращается на экран и проверяются кадры |
| Окно само меняет размер (от него тянутся облачко реплик и поле ввода на весь экран) | Переезд идёт только через `setBounds` с размером, который попросила страница; плюс сторож раз в 3 секунды возвращает размер, если он уехал (проверяется протяжкой в 120 шагов) |
| Запущено два окна, они спорят за позицию | Второй экземпляр не открывается; `start.bat` гасит прошлое окно |

### Проверка в браузере

Оболочка не обязательна: персонаж открывается и в браузере.

```bash
cd server && go run ./cmd/companion      # открой http://127.0.0.1:8787
```

1. Персонаж по центру, слева внизу — зелёная точка и имя.
2. Клик по персонажу — окно ввода; напиши что-нибудь и нажми `Enter`.
3. Она «думает» (точки в облачке), затем отвечает — это настоящий NVIDIA NIM.
4. Погладь её по голове (быстро поводи мышью по волосам) — сердечки и улыбка.
5. Напиши ей «я ухожу» и оставь мышь в покое (или дождись idle-повода в
   ускоренном прогоне) — она засыпает прямо во фразе, глаза закрыты, над
   головой летают «Zzz».
6. Браузер **не** перезаписывает сохранённую позицию при переподключении: у
   страницы нет окна, и она не имеет права двигать настоящего персонажа.
7. (оболочка) Оставь мышь в движении, но сам молчи 5–60 минут на свободном
   месте — время от времени она погуляет по столу и развернётся у края экрана;
   взяв её мышью — остановишь.
8. Кликни по ней (не тащи) — в облачке появится короткая фраза, и она откроет
   поле ввода; спящая — проснётся. Десять секунд подряд её тыкать бесполезно:
   дальше поле ввода откроется молча.
9. Спроси её что-нибудь — ответ она произнесёт вслух (голос из Edge TTS,
   реплика появится в облачке чуть раньше звука). В меню есть переключатель
   «говорит вслух»; вторая такая же фраза звучит сразу (кэш). В облако
   Microsoft при этом уходит только текст её ответа.
10. Нажми кнопку микрофона в поле ввода и скажи что-нибудь вслух (кнопка
    пульсирует красным) — нажми ещё раз, чтобы остановить. Расшифрованный
    текст появится в поле ввода; отправь его как обычно. Живой микрофон
    разрешён оболочке ровно на одно право (media); расшифровка идёт на этой
    машине, запись с микрофона не отправляется никуда и стирается сразу.
11. Включи в меню «слышит её имя» (нужен `wake.enabled: true` в конфиге) —
    в углу окна загорится зелёная точка: она слушает. Скажи «Мира, привет!» —
    она оживёт, машет и ответит на имя, а «Мира, которое время?» — ответит по
    сути, как на напечатанное. Скажи что-то без её имени — она не отреагирует.
    Выключи переключатель — точка погаснет, микрофон закроется.
12. Alt+F4 по окну — она спрячется в трей (значок — её текущий вид). Двойной
    клик по значку — она снова на экране, в прежнем месте и позе. Включи галку
    «запускать при входе» и открой вкладку «Автозагрузка» Диспетчера задач —
    там появилась запись Electron с папкой `Friend\desktop`; выключи галку —
    запись пропала. «Выход» из меню трея — закрывает её и гасит сервер.
13. Посадка «на окне»: открой любое окно (браузер, редактор), выбери в меню
    «на окне» — она сядет на его верхнюю кромку. Переключись в другую программу
    — она переедет на её верх. Тащи её мышью так, чтобы ноги вошли в верхнее
    окно, и держи секунду — она сядет сама; пролети через кромку быстро —
    сядет не должна. Рабочий стол без окон — скажет «не на что сесть» и
    останется свободной.
14. Ползунок «следит за курсором»: поставь 0 — зрачки стоят по центру и курсор
    их не сдвигает; 50 — следят за курсором наполовину; 100 — провожают курсор
    до упора в край глазницы (дальше одного пикселя спрайта не выезжают
    никогда). Значение переживает перезапуск.
15. Настроение у неё видно не только на лице, но и в голосе: после грустной
    реплики («мне грустно») следующие фразы звучат медленнее и ниже, после
    радостной — быстрее и выше; сонная она говорит заметно медленно.
16. Включи «танцует под музыку» и включи музыку в любой программе (плеер,
    видео, игра) — через пару секунд она начинает подпрыгивать в такт,
    качает волосами и поднимает руку на «раз-два»; её собственная озвучка
    тоже попадает в микшер, но её собственный голос танец НЕ продлевает:
    музыка кончилась — секунд через восемь танец заканчивается, даже если
    она продолжает говорить, лицо возвращается к настроению. Из звукового
    сигнала в программе живёт только уровень громкости: записи звука нет ни
    в памяти, ни в сети.
17. Оставь компьютер в покое минут на десять — она заснёт (глаза закрыты,
    «Zzz»). Не возвращайся минут тридцать — она «уйдёт» к ближайшему краю
    экрана и заснёт там; подведи мышь к кромке — выглянет. Вернись (любая
    мышь/клавиатура) — оживёт и вернётся ровно на своё место. Занятую
    (разговор, меню, её держат, танцует, гуляет) сон не трогает.
18. Посиди рядом с ней молча пару минут, не трогая мышь к ней — раз в
    полминуты-минуту она должна «оживать»: потянуться обеими руками,
    почесать затылок, ёрзнуть или посмотреть на свою ладошку. Во время
    разговора, шага, танца и сна этих движений нет.
19. Оставь её в тишине минут на восемь (мышь в покое, не говори) — примерно
    через каждые пять минут она может решиться на **длинный проход**: дойдёт
    до дальнего края стола, развернётся и перейдёт на другой край — через
    весь экран, шагая с видимыми ногами, — и остановится. Обычная короткая
    прогулка («рядом и молчишь») остаётся: 8–16 секунд туда-сюда.
20. Напиши ей что-то грустное («мне сегодня грустно…») — она ответит мягче
    обычного, а договорив, на несколько секунд станет грустнее (лицо «sad»),
    потом вернётся к своему спокойному лицу. Напиши радостно («ура, сделал!») —
    улыбнётся. Нейтральную просьбу («открой файл») её лицо не тронет. Она не
    объявит, что «проанализировала тебя», — тон её ответа просто станет
    соответствующим.

## Конфиг

По умолчанию файла нет — работают значения из `config.Default()`. Пример:

```bash
cp config.example.json "$APPDATA/Friend/config.json"   # Windows
```

Поля, которые чаще всего правят: `avatar.name`, `avatar.width/height`,
`persona.file` (свой характер), `llm.model`, `llm.max_tokens`,
`llm.history_messages`, `llm.timeout_sec`.

Инициатива настраивается в секции `proactive`: `tick_seconds` (как часто
смотреть обстановку), `min_gap_minutes` (анти-спам, при занятости удваивается),
`food_reminder_minutes` (вода/еда), `quiet_from_hour`/`quiet_to_hour` (окно
тишины). Логи — секция `log` (`{"level": "debug"}` — видно каждый тик и поводы).

Файл памяти — `paths.memory_file` (по умолчанию `%AppData%\Friend\memory.db`,
там же и `state.json`); переменная `FRIEND_MEMORY_FILE` перекрывает. Папка
внешнего арта — `paths.sprites_dir` (по умолчанию `%AppData%\Friend\sprites`);
переменная `FRIEND_SPRITES_DIR` перекрывает. Озвучка — секция `voice`
(`enabled`, `edge_voice`, `speed`), голосовой ввод — секция `stt` (`enabled`,
`model_dir` — папка модели faster-whisper, по умолчанию
`%AppData%\Friend\stt-model\faster-whisper-base`; переменная `FRIEND_STT_MODEL`
перекрывает), wake word — секция `wake` (`enabled`, по умолчанию false:
постоянно слушать микрофон человек включает сам; требует включённого `stt`).

Переменные окружения перекрывают файл: `FRIEND_ADDR`, `FRIEND_NAME`,
`FRIEND_STATE_FILE`, `FRIEND_LOG_LEVEL`, `FRIEND_API_KEY_ENV`,
`FRIEND_PERSONA_FILE`, `FRIEND_ENV_FILE` (путь к своему файлу ключей).

### Характер

Характер живёт отдельным файлом и встроен в бинарник. Свой файл:

```bash
cd server
go run ./cmd/companion -dump-persona > my-persona.json   # шаблон
```

Правь `name`, `gender`, `tone`, `style`, `rules`, `examples` — и укажи путь в
`persona.file`. Ключевое поле про речь: `gender` (`female`/`male`) — без него
модель путает род в русском.

Ключа API в конфиге НЕТ и быть не должно: там только имя переменной окружения.

## Полезные команды

```bash
cd server
go test ./...            # тесты
go test -race ./...      # гонки (состояние пишут и хаб, и разговор)
go vet ./...
go run ./cmd/companion -addr 127.0.0.1:9000 -web ../web   # другой порт

```

## Протокол (JSON поверх WebSocket)

`server/internal/server/protocol.go`:

| Кто | Кадр | Смысл |
|---|---|---|
| клиент → сервер | `{"type":"hello","client":"electron","version":1}` | представление, версия протокола |
| сервер → клиент | `{"type":"welcome","state":{…},"avatar":{…},"history":[…]}` | кто в окне, где окно, что уже сказано |
| клиент → сервер | `{"type":"position","x":1176,"y":324}` | окно переехало |
| сервер → клиент | `{"type":"state","position":{…},"saved":true}` | записано на диск |
| сервер → клиент | `{"type":"state","mood":{"mood":0.62,"energy":0.45,"affection":0.51,"band":"mid"}}` | настроение сдвинулось заметно: по `band` меняется «лицо покоя» |
| клиент → сервер | `{"type":"say","text":"привет"}` | реплика человека; `text` с префиксом `запомни:` — команда памяти (ответ работает без ключа модели) |
| клиент → сервер | `{"type":"focus","app":"goland64.exe","title":"main.go — GoLand","idle":45}` | у человека сменилось окно или истёк heartbeat; `idle` — минут без мыши |
| сервер → клиент | `{"type":"thinking","on":true}` | она думает |
| сервер → клиент | `{"type":"reply","text":"…","at":"…","proactive":false,"emotion":"sleep"}` | её реплика; `emotion` приходит только с особым лицом реплики (сейчас — «sleep» при её засыпании), `proactive` — когда заговорила сама |
| сервер → клиент | `{"type":"reply_error","error":"…"}` | ответ не получился (текст для человека) |
| клиент → сервер | `{"type":"ping"}` | проверка живости |

Ответ модели считается в ОТДЕЛЬНОЙ горутине на соединение: иначе на время ответа
(секунды) окно перестало бы принимать кадры перетаскивания и застыло. Реплики
стоят в очереди (3 штуки) — вторая не теряется, а поток ругается «я ещё не
договорила» вместо бесконечного накопления.

Соединение принимается только с локальных Origin (`127.0.0.1`, `localhost`,
`tauri://localhost`): иначе любая открытая вкладка браузера могла бы управлять
персонажем через `ws://127.0.0.1:8787`.
